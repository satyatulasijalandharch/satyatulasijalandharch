# Portfolio Website Architecture

This document describes the portfolio site as it is currently implemented. The project is a statically generated Astro site, with page routes under `src/pages/`, structured content managed by Astro Content Collections, and shared UI in `src/components/`.

## Technology and Configuration

- **Astro** builds the site as static output. The production build is written to `dist/`.
- **TypeScript** provides types for Astro routes, content entries, and configuration.
- **Tailwind CSS 4** is loaded from `src/styles/global.css` and integrated through `@tailwindcss/vite`.
- **Markdown** powers authored work and blog content through Astro's content collections.
- **Astro Content Collections** define and validate work, blog, certification, and experience entries.
- **Astro Assets** optimize local images. `Portrait.astro` uses `Image`; `BaseLayout.astro` uses `getImage` for social preview images.
- **RSS** is generated by `@astrojs/rss` at `/rss.xml` from published blog entries.
- **Sitemap** generation is enabled through `@astrojs/sitemap`.

`astro.config.mjs` sets the production site URL to `https://stjch.in`, enables the React and sitemap integrations, adds Tailwind's Vite plugin, and configures the Fontsource font provider. React and its integration are installed/configured, though current page rendering uses Astro components.

`tsconfig.json` extends Astro's strict configuration and defines these aliases:

| Alias | Target |
| --- | --- |
| `@components/*` | `src/components/*` |
| `@layouts/*` | `src/layouts/*` |
| `@assets/*` | `src/assets/*` |
| `@styles/*` | `src/styles/*` |
| `@content/*` | `src/content/*` |

## Project Structure

```text
src/
├── assets/                 # Local assets, including the profile image
├── components/
│   ├── about/              # About-page skill and academic items
│   ├── home/               # Homepage sections and metric item
│   ├── layout/             # Shared header, footer, and container
│   ├── CertCard.astro      # Shared credential row/card
│   ├── Portrait.astro      # Optimized reusable profile portrait
│   ├── ProjectCard.astro   # Shared work/project card
│   └── ResumeButton.astro  # Shared resume link/button
├── content/
│   ├── blog/               # Blog Markdown entries
│   ├── certs/              # Certification JSON data
│   ├── experience/         # Experience JSON data
│   └── work/               # Work/project Markdown entries
```

Top-level configuration and supporting files include `astro.config.mjs`, `tsconfig.json`, `package.json`, `package-lock.json`, `public/` static assets, and this `docs/` directory.

## Pages and Routes

Astro derives URLs from files in `src/pages/`:

| File | Route | Purpose |
| --- | --- | --- |
| `src/pages/index.astro` | `/` | Homepage; queries collections and composes homepage sections |
| `src/pages/about.astro` | `/about` | Biography, portrait, skill list, academic background, and publication |
| `src/pages/certs.astro` | `/certs` | Certification listing |
| `src/pages/blog/index.astro` | `/blog` | Published blog index, ordered newest first |
| `src/pages/blog/[id].astro` | `/blog/<id>` | Static blog detail routes generated from the blog collection |
| `src/pages/work/index.astro` | `/work` | Work/project index |
| `src/pages/work/[id].astro` | `/work/<id>` | Static project detail routes generated from the work collection |
| `src/pages/404.astro` | `/404` | Not-found page |
| `src/pages/rss.xml.ts` | `/rss.xml` | RSS feed for non-draft blog posts |

`BaseLayout.astro` supplies the shared header, footer, content container, canonical URL, Open Graph and Twitter metadata, icons, and the RSS auto-discovery link. Individual pages pass their title and description to this layout.

## Shared Components

### Site layout

- `src/components/layout/Container.astro` provides consistent page width and horizontal spacing.
- `src/components/layout/SiteHeader.astro` renders site navigation and the resume action.
- `src/components/layout/SiteFooter.astro` renders social/contact links and the RSS link.

### Shared content components

- `src/components/Portrait.astro` renders the optimized profile image and accepts sizing and styling props.
- `src/components/ProjectCard.astro` presents a work collection entry.
- `src/components/CertCard.astro` presents a certification entry.
- `src/components/ResumeButton.astro` centralizes the resume link treatment.
- `src/components/about/SkillCard.astro` renders one skill category with slotted detail text.
- `src/components/about/AcademicRow.astro` renders an academic or publication title, optional date, and slotted description.

### Homepage sections

`src/pages/index.astro` retrieves collection data, sorts and limits it, then passes it into these section components:

- `HeroSection.astro` renders the profile and introduction.
- `ImpactMetrics.astro` renders the impact metrics using `MetricItem.astro`.
- `FeaturedWork.astro` renders selected project cards.
- `ExperienceSection.astro` renders career history.
- `RecentPosts.astro` renders recent published blog entries.
- `CertsSummary.astro` renders a short certification summary.

## Content Collections

Collections are declared in `src/content.config.ts` using Astro loaders and Zod schemas:

| Collection | Source | Main fields |
| --- | --- | --- |
| `work` | `src/content/work/*.md` via `glob()` | `title`, `description`, `period`, `company`, `role`, `metric`, `stack`, `featured`, `order`, optional image `cover` |
| `blog` | `src/content/blog/*.md` via `glob()` | `title`, `description`, `pubDate`, optional `updatedDate`, `topic`, `readTime`, `draft`, optional image `cover` |
| `certs` | `src/content/certs/certs.json` via `file()` | `id`, `name`, `issuer`, `issueDate`, optional `validUntil`, `credentialUrl`, optional `skills` |
| `experience` | `src/content/experience/experience.json` via `file()` | `id`, `period`, `role`, `company`, optional `location`, `focus`, `stack`, optional `highlights`, `order` |

The schemas are the source of truth for content fields and defaults. Blog pages and the RSS endpoint filter out entries where `draft` is true. Work entries use their collection IDs for detail URLs; blog entries use their IDs under `/blog/`.

## Packages

The versions are maintained in `package.json` and `package-lock.json`.

| Package | Role in this project |
| --- | --- |
| `astro` | Framework, static build, routing, assets, and content APIs |

| `tailwindcss` | Utility CSS framework |
| `typescript` | TypeScript compiler and language support |
| `react`, `react-dom` | React runtime dependencies for the configured React integration |
| `@types/react`, `@types/react-dom` | React TypeScript declarations |

## Common Commands

```sh
npm install
npm run dev
npm run check
npm run build
npm run preview
```

- `npm run dev` starts the Astro development server and binds it to the host interface.
- `npm run check` runs `astro check` for Astro and TypeScript diagnostics.
- `npm run build` creates the static site in `dist/`, including generated routes, optimized assets, sitemap, and RSS feed.
- `npm run preview` serves the built site locally for production-style review.
